# 제품 리뷰: 잘 팔리려면 무엇을 고쳐야 하나 (2026-11)

## 한 줄 결론

보안·멱등성·권한(RLS) 같은 기술 기반은 탄탄합니다. 그런데 **돈을 받는 길**과 **핵심 기능(문서 → 할 일)**이 둘 다 끊겨 있어서, 리뷰 시점 상태로는 팔 수 없었습니다.

## 2. 사업 구조에 대한 비판 (코드만으로는 못 고치는 것 포함)

- **"범용 워크스페이스"라는 포지셔닝이 약합니다.** 노션, 할 일 앱, 카톡 '나와의 채팅' 같은 무료 대체재와 정면으로 붙게 됩니다. 이길 수 있는 지점은 하나, **"종이 서류가 마감일 있는 할 일이 된다"**입니다. 소개 문구를 전부 그쪽으로 바꿨습니다.
- **유료 가치가 늦게 체감됩니다.** 기존 설계의 유료 가치는 "30일 지난 서류 검색"에 쏠려 있어서, 가입하고 한 달이 지나야 아쉬움을 느낍니다. 첫 주 안에 "와" 하는 순간이 필요합니다. 이번에 넣은 **마감일·금액 자동 감지**가 그 역할을 하도록 무료로 열어 두었습니다.
- **무료 팀이 10명까지 공짜였습니다.** 팀이 돈을 낼 이유가 사실상 없었습니다. 새로 만드는 무료 팀은 3명까지로 바꿨고(기존 팀은 그대로 유지), 4번째 사람이 들어오려 할 때가 팀 플랜으로 넘어가는 자연스러운 계기가 됩니다. 되돌리려면 `apps/web/src/lib/plans.ts`의 `FREE_TEAM_MAX_SEATS`를 10으로 바꾸면 됩니다.
- **"30일 후 원본 삭제"는 불안을 줍니다.** 계약서 같은 서류가 지워진다고 느끼면 업그레이드보다 이탈이 먼저 옵니다. "본문·요약·할 일은 계속 남고, 원본 파일만 정리된다"는 점을 요금제·설정·FAQ에 분명히 적었습니다.
- **이름 `Workspace`는 불리합니다.** 검색도 상표 등록도 어렵고, 기억에도 남지 않습니다. 이름은 `apps/web/src/lib/brand.ts` 한 곳에서 바꿀 수 있게 모아 두었습니다.
- **측정 장치가 없었습니다.** 설계서가 스스로 "유료 전환율은 검증이 필요한 가설"이라고 적어 두고도, 그걸 잴 방법이 없었습니다. 이제 업그레이드 클릭은 모두 `billing_upgrade_intents`에 어느 화면에서 눌렀는지(`source`)와 함께 쌓입니다.
- **AI 연결이 실제 서비스와 맞지 않았습니다.** `packages/ai/worker.ts`가 OpenAI 형식이 아닌 자체 JSON을 보내고 있어서, `.env.example`대로 OpenAI 주소를 넣으면 실패했습니다. 이후 OpenAI 호환 API 형식으로 다시 썼습니다.

## 4. 가격에 대해

`src/lib/plans.ts`의 가격(프로 월 ₩6,900 / 연간 결제 시 월 ₩5,900, 팀 인당 월 ₩8,900 / ₩7,900)은 **제안값**입니다. 확정 전에 꼭 확인하세요.

- 프로 한도(월 OCR 500쪽, 받아쓰기 300분)를 꽉 채우는 사용자는 AI 원가가 상당히 나올 수 있습니다. 실제로 쓸 AI 공급자의 단가를 넣어 최악의 경우를 계산하고, 가격을 내리려면 한도도 같이 내리세요.
- `billing_upgrade_intents`에 쌓이는 신청 수를 보고 가격을 조정하는 것을 권합니다. 신청이 너무 적으면 가치 전달이나 가격 문제, 너무 많으면 가격을 올릴 여지가 있다는 뜻입니다.
